# Getting Started (No experience needed)

GitHub is a website for storing and sharing files. A repository (repo) is a project folder on that website. This kit is free. Creating a template copy or a fork needs a GitHub account; downloading the ZIP or cloning this public repository does not. Choose just one option below.

## Option A: Use this template (recommended)

A template makes an independent copy that belongs to you.

1. Open [the original repository](https://github.com/ctrl-jo/upskill-in-public) and sign in to GitHub, or select **Sign up** to create a free account.
2. On the repository's **Code** tab, find the green **Use this template** button above the files. Select it, then **Create a new repository**. If the button is missing, use Option B below.
3. Under **Owner**, choose your account. Under **Repository name**, enter `my-upskill-journey` (or another unused name).
4. Choose **Public** if you want to showcase your learning. Anyone can then see your notes and your progress history. Choose **Private** only if you want to practice first. You can change this later in Settings. Leave **Include all branches** unchecked if shown.
5. Select **Create repository**. Wait for your new repository to open.
6. Check that your username and repository name appear above the files. Bookmark this page. If you leave it, open your GitHub profile, select **Repositories**, then open `my-upskill-journey`.
7. In your own copy, open the root `README.md` and select the pencil icon (**Edit this file**). Replace its title and the opening text through **Why this exists**, including the TikTok screenshot line, with your own introduction, chosen path, and learning goal. For example: “I'm Alex, learning web development. My first goal is to build a study checklist.” Select **Commit changes**, then confirm the save.
8. Continue with **Your first 30 minutes** below. You can write your first log entirely on GitHub; no installation is needed.

### Change visibility later

1. Open your own repository on GitHub and select **Settings**. If the tab is hidden, look in the menu beside the repository tabs.
2. Select **General** in the settings sidebar.
3. Scroll down to **Danger Zone**.
4. Beside **Change repository visibility**, select **Change visibility**, then **Change to public** or **Change to private**.
5. Read GitHub's explanation and follow its confirmation prompts for the correct repository. Before making it public, follow the [privacy reminder](my-learning/README.md#before-you-make-this-public). Changing back to Private does not remove copies other people already made.

## Option B: Download as ZIP (no GitHub account needed)

A ZIP is one compressed file that contains the whole folder.

1. Open [the original repository](https://github.com/ctrl-jo/upskill-in-public).
2. Select the green **Code** button above the files, then **Download ZIP**.
3. Find the downloaded ZIP in your Downloads folder. On Windows, right-click it, select **Extract All**, then **Extract**. On macOS, double-click it. On Linux, right-click it and choose your archive tool's extract option.
4. Open the extracted `upskill-in-public-main` folder. If it contains another folder with that name, open that too until you see `README.md`.
5. Open `README.md` with any text editor, such as Notepad, or open the entire folder in a text editor that supports folders. If asked which app to use, select your text editor. Work in the extracted folder, not inside the ZIP.
6. Continue with **Your first 30 minutes** below. Local changes stay on your computer until you choose to share them.

### Tip: Make a ZIP-based journey public

A ZIP stays on your computer. It is not public until you upload your work to your own Public GitHub repository.

1. When you want to showcase your learning, follow **Option A** above to create your own Public copy.
2. Open `my-learning` in that copy. Select **Add file**, then **Upload files**, and choose your own notes or project files from the extracted folder on your computer. Upload only files you want to share, not the ZIP itself.
3. Select **Commit changes** to save the uploaded work. Earlier edits on your computer do not become separate GitHub history entries; future saves on GitHub can show your progress over time.

## Option C: Fork or clone (if you already know Git)

Git tracks file changes. A fork is a GitHub copy connected to the original project. A clone is a local copy made with Git.

1. For a copy you can push changes to, select **Fork**, then **Create fork** on the original repository, or use Option A.
2. On your copy, select **Code**, copy its HTTPS address, then run `git clone YOUR-COPIED-URL` in a terminal. Replace `YOUR-COPIED-URL` with that address.
3. Open the cloned folder. Cloning the original repository instead is fine for reading, but does not give you permission to push changes to it.

## How to read the files

Files ending in `.md` are Markdown: ordinary text files with simple marks for headings and links. VS Code and Obsidian are optional editors that can display them. GitHub displays them directly.

1. On GitHub, click a folder name to enter it, then click a `.md` file to read it. Use your browser's Back button to go back.
2. On your computer, open a `.md` file in your text editor. If links are not clickable, use the path in parentheses to find the file inside your extracted or cloned folder.
3. When editing, keep the headings (lines beginning with `#`) and replace the bracketed example text with your own words.

## Make your progress visible

Sharing is optional, and private practice counts. When you want to showcase your skills, a Public copy lets other people see your work.

1. Make sure your own copy has the **Public** label beside its name. If it says **Private**, follow **Change visibility later** above when you are ready.
2. Save each daily log with **Commit changes** and confirm the save. A commit is a saved change; GitHub records a date and the changed files. Use an honest description of what you practiced. Local Git commits need to be pushed (sent to GitHub) before other people can see them.
3. Open your repository's **Code** tab. Above the file list, select the commit count or clock icon to open **Commits**. This is your timeline of saved changes. Select an entry to see what changed. If you cannot find it, add `/commits/main/` to your repository's web address; this kit uses `main` as its main branch (version of the files).
4. Return to your repository's main page and copy its address from the browser, such as `https://github.com/YOUR-USERNAME/my-upskill-journey`. Copy your own link, not the original kit's link.
5. Put that link in a social bio or a post when you feel ready. A short sentence about what you learned helps people understand the work. There is no daily posting requirement.
6. Pin the repository on your GitHub profile so visitors can find it: select your profile picture, **Your profile**, then **Customize your pins** beside **Popular repositories** or **Pinned**. Select your repository and choose **Save pins**.

## Where do I put my own work?

Your own notes, logs, and projects belong in [my-learning/](my-learning/README.md) in your copy. Everything in `paths/` is a guide or example to read. You do not need to change those files to study. Work saved in a public repository can be read by anyone.
